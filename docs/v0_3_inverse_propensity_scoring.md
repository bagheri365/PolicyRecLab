# v0.3 — Inverse Propensity Scoring

## Research question

Once contextual support holds and behavior propensities are known, can inverse
propensity scoring recover the value of a fixed target policy from logs
generated by a different behavior policy?

## Estimator

For logged interactions

```math
(x_i, a_i, r_i, \pi_b(a_i \mid x_i))
```

and a fixed target policy \(\pi_e\), define

```math
w_i =
\frac{
\pi_e(a_i \mid x_i)
}{
\pi_b(a_i \mid x_i)
}
```

The inverse propensity scoring estimator is

```math
\hat V_{\mathrm{IPS}}
=
\frac{1}{n}
\sum_{i=1}^{n}
w_i r_i
```

Under the baseline one-step setting, known/correct behavior propensities,
support, and standard sampling assumptions, IPS is unbiased for the value of a
fixed target policy.

## Controlled validation

v0.3 logs data under an epsilon-greedy behavior policy and evaluates a
deterministic greedy target policy.

Because `epsilon > 0`, every action has positive behavior probability. The
target is therefore supported.

The simulator supplies the exact finite-population target value:

```math
V_{\mathrm{finite}}(\pi_e)
=
\frac{1}{N}
\sum_x
\sum_a
\pi_e(a \mid x)\mu(x,a)
```

The IPS estimate is compared directly against this known quantity.

## Required sanity check

When target policy equals behavior policy,

```math
\frac{
\pi_e(a_i \mid x_i)
}{
\pi_b(a_i \mid x_i)
}
=1
```

for every logged interaction. Therefore IPS must reduce exactly to the ordinary
logged sample mean, apart from floating-point arithmetic.

This identity is an automated test.

## Propensity integrity

The estimator cross-checks the supplied behavior-policy matrix against the
propensity recorded in each logged interaction. A mismatch is treated as an
error rather than silently producing an OPE number.

## Identification boundary

IPS refuses to evaluate a target policy with exact contextual support
violations. For example, deterministic greedy behavior cannot nonparametrically
identify a uniform target policy.

No estimator implementation should turn an identification failure into a
numeric result merely because division can be guarded in code.

## Interpretation boundary

The ordinary logged mean is an on-policy estimate of the behavior policy's
value. IPS reweights those observations to target a different supported policy.

v0.3 does **not** claim that IPS is low variance or practically reliable under
all supported policies. Very small positive behavior propensities can produce
large importance weights even when exact support holds.

That is the subject of v0.4.

## Non-goals

v0.3 does not implement:

- clipping,
- SNIPS,
- direct method,
- doubly robust estimation,
- confidence intervals,
- adaptive-logging inference.

## Next milestone

v0.4 studies weak overlap and importance-weight variance while keeping exact
support intact.
