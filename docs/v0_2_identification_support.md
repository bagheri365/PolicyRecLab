# v0.2 — Identification, Positivity, and Support

## Research question

Before choosing an off-policy estimator, can the target policy value be
identified from data generated by the behavior policy?

## Positivity / support condition

For every context-action pair that the target policy may choose,

\[
\pi_e(a \mid x) > 0
\quad \Longrightarrow \quad
\pi_b(a \mid x) > 0.
\]

If this condition fails, the behavior logs contain no direct information about
the reward of that action in that context. In the standard nonparametric
one-step contextual-bandit setting, the full target policy value is therefore
not identified from those logs alone.

This is an **identification failure**, not merely a high-variance estimation
problem.

## Controlled cases

All three cases use the same synthetic reward environment.

### 1. Uniform behavior → greedy target

Uniform behavior assigns positive probability to every action in every context.

**Expected status:** supported / identifiable under the baseline assumptions.

### 2. Epsilon-greedy behavior → uniform target

For `epsilon > 0`, epsilon-greedy assigns

\[
\epsilon / |A|
\]

to every non-greedy action and positive probability to the greedy action.

**Expected status:** supported. Small epsilon may create weak overlap, but that
is not the same as zero support. Weak-overlap variance is deferred to v0.4.

### 3. Deterministic greedy behavior → uniform target

Deterministic greedy logging assigns probability one to a single action and
zero to all others. A uniform target assigns positive probability to every
action.

**Expected status:** not nonparametrically identified.

## Diagnostics

v0.2 reports:

- whether full contextual support holds,
- number and fraction of contexts with violations,
- number of violating context-action pairs,
- average target-policy probability mass off support,
- maximum context-level target mass off support,
- minimum positive behavior probability on target support.

The final metric is descriptive only in v0.2. Very small positive propensities
will matter for importance-weight variance later.

## Important interpretation boundary

Global catalog coverage is not contextual positivity. An action can appear
somewhere in the logs while still having zero behavior probability in contexts
where the target policy wants to choose it.

Likewise, more data do not repair exact zero support. Repeating a deterministic
logging policy forever still never reveals rewards for actions it never chooses.

## Non-goals

v0.2 does not implement:

- IPS,
- clipped importance weights,
- SNIPS,
- direct reward modeling,
- doubly robust estimation,
- confidence intervals.

Those methods cannot solve a target-policy identification failure without
additional structural/modeling assumptions.

## Next milestone

v0.3 introduces inverse propensity scoring only for target/behavior policy pairs
that pass the support check.
